---
title: MULTIPLE_SUBGRAPHS
---

<Note>
In current versions of LangGraph, this error is unlikely to occur. LangGraph automatically assigns position-based namespace suffixes to subgraph invocations (e.g., `calling_node`, `calling_node|1`), preventing namespace conflicts even with `checkpointer=True`. The information below is retained for reference and for older versions.
</Note>

This error occurs when you [call a subgraph inside a node](/oss/python/langgraph/use-subgraphs#call-a-subgraph-inside-a-node) multiple times, and the subgraph is compiled with `checkpointer=True` (continuations mode). In older versions, multiple invocations could write to the same checkpoint namespace and conflict.

## Troubleshooting

Choose one of the following based on your requirements:

1. **Don't need interrupts?** Use `checkpointer=False` to opt out of checkpointing entirely:
   ```python
   subgraph = subgraph_builder.compile(checkpointer=False)
   ```

2. **Need interrupts but not cross-invocation persistence?** Use the default inherited mode by omitting `checkpointer`:
   ```python
   subgraph = subgraph_builder.compile()
   ```
   Each invocation gets a unique namespace, so parallel execution works. The subgraph starts fresh each time but can use `interrupt()`.

3. **Need cross-invocation persistence?** Use `checkpointer=True`. In current versions, LangGraph assigns each invocation a position-based namespace suffix (`calling_node`, `calling_node|1`, etc.) to prevent conflicts. For stable, name-based namespaces, wrap each subgraph with a unique node name — see [multiple subgraphs with `checkpointer=True`](/oss/python/langgraph/use-subgraphs#multiple-subgraphs-with-checkpointertrue).
